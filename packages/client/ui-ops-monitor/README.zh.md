# @deepseek-ai/dsh-client-ui-ops-monitor

[English](README.md) | 中文

## 概述

为 Web 配置添加运维大屏。选择已保存的 SSH 服务器和经审查的 Linux 模板，在 Host 运行期间持续采集、查看最近历史，并向小 C 查询指标。此可选配置包依赖现有远程运维工作区及存储服务。凭据由远程运维保存，定时采集不需要调用模型。

## 使用此包

在已构建的源码目录中，将本地配置包安装到 Web 配置：

```sh
pnpm dsh plugin --profile web add ./packages/client/ui-ops-monitor
```

通过 `dsh` 启动 Web 配置。先在远程运维中保存并验证服务器，再打开运维大屏，从监控管理中点击接入监控，选择服务器并查看脚本。启用所选模板即授权持续采集。暂停采集保留历史，重新配置并启用会替换该主机的历史。仅打开大屏不会授权 SSH 访问。

监控数据加载中或失败时，管理 SSH 服务器入口仍可使用。缺少远程运维面板时会显示安装提示，可通过管理插件进入插件管理。流读取失败会显示诊断码，不展示服务端错误详情。监控服务需要远程运维后端和存储服务，仅导入浏览器资源不能启动采集。

Linux 基础健康采集一秒间隔的 CPU 使用率、基于 MemAvailable 的内存使用率、一分钟负载与运行时长。文件系统模板采集容量使用率和挂载名称。命令失败、输出截断或格式不符时丢弃该模板的字段；其他模板成功采集的指标保留为部分成功采样，并附带各模板的失败详情。大屏展示时间戳，超过两倍配置采集间隔的数据标记为过期。

大屏根据已接入模板的定义生成趋势图和排行图，并展示采集状态及主机资源热力矩阵。图表视图可以选择全部图表、基础总览或单个模板，主机筛选作用于所有面板。热力矩阵和磁盘排行仅使用启用中主机最新完整或部分成功采样中的有效字段；矩阵中的磁盘值取该主机各文件系统的最大使用率。历史趋势保留时间戳与缺失断点。接入、历史明细和暂停操作位于监控管理中。

通过主机筛选或点击资源热力矩阵中的主机名称进入单机大屏。页面展示该主机的地址、采集状态、最近采样时间、CPU 与内存仪表、负载、运行时长和模板图表。集群数量与分布图替换为主机读数，“问小 C”针对当前主机，“返回集群总览”恢复所有主机。暂停、过期或不可用的当前读数留空，历史曲线仍保留。

新增的可选模板采集内存与文件系统容量、各网卡计数器，以及 CPU 和内存占用前十的进程。容量条形图以二进制单位展示已用量与总量。进程采集依赖 GNU ps，仅保留进程名称和 PID，不采集完整命令参数；多核系统的进程 CPU 使用率允许超过 100%。已有主机仍使用原先选择的模板，新增模板需要显式配置。

网络图表通过相邻采样中启动标识与网卡标识一致的计数器计算每秒速率。首次采样、中间采集失败、计数器下降或启动标识变化时保留速率断点；计数器不变时速率为零。时间间隔取 Host 收到数据的时间。模板声明字段类型、单位、实例标签、采集优先级和默认面板。优先级决定串行执行顺序；单个模板失败不会阻止后续模板，除非该服务器的采集时限已到。这是固定的类型化目录，不是 HertzBeat YAML 导入器或表达式解释器。

可以对小 C 说“使用 Linux 模板监控这台已保存的服务器”或“查看最新的 CPU 和内存指标”。通过模型接入时会针对脚本和采集间隔请求会话审批。查询已存指标不会执行远程命令。凭据在远程运维中配置，不通过聊天发送。

`ui-ops-monitor` 配置行接受 `intervalMs`（60000）、`timeoutMs`（15000）、`maxServers`（20）、`historyPoints`（120）和 `streamIntervalMs`（5000）。各服务器串行采集，轮次不重叠；单轮耗时超过间隔时会推迟下一轮。配置和采样历史通过存储提供者保留，Host 重启后恢复。存储失败会停止采集并报告，请检查存储后再重启插件。

## 了解实现

<details>
<summary>实现细节</summary>

配置包插入 Host 和 Client 插件行。Host 复用远程运维中固定指纹的连接，将接入授权绑定到已审查的地址、用户名、认证方式和主机密钥；身份变更后需要重新接入。带版本的 `ops_monitor` 存储域保存各主机的有限历史。浏览器通过共享资源流读取数据，关闭浏览器资源不会停止采集。卸载时先取消并等待采集结束，再关闭存储。

模板参考 HertzBeat 将采集命令与指标定义分离的方式，采用本插件固定的制表符分隔数值格式。采集脚本为独立实现，不提供通用 HertzBeat YAML 解释器。参考设计见 [HertzBeat SSH 监控](https://hertzbeat.apache.org/docs/1.9.0/advanced/extend-ssh/)。

</details>

## 模型体验

### 监控工具

#### 模型看到什么

`monitoring_catalog` 列出已保存主机的元数据和经审查的脚本。`monitoring_enable` 经会话审批后接入主机，`monitoring_disable` 暂停采集，`monitoring_query` 返回带时间戳的有限采样。调用和结果使用现有工具记录，不返回原始命令输出或 SSH 凭据。

#### Token 影响

四个工具声明与查询结果增加 token。后台采集不会产生模型请求或自动注入上下文。

#### KV Cache 影响

指标变化时工具声明保持稳定。主机列表和指标仅通过主动调用的工具结果进入上下文。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 仅支持 Linux，需要 POSIX shell、awk、sleep、df 和可读的 procfs。不提供 Windows 服务器采集、跳板机或远程辅助程序。
- 不包含自定义脚本、自定义指标、面板布局编辑、告警通知和 HertzBeat YAML 导入。历史按采样点数限制，不提供长期时序数据库。
- 采集要求 Host 持续运行。串行采样适合小规模主机，时间戳为 Host 接收时间。失败采样保留缺口，不以零替代缺失指标。
- 此可选配置包面向具有远程运维能力的 Web 配置。安装不会预置服务器或凭据。真实基础设施访问需要在部署环境验证，自动化测试使用隔离的 SSH 响应。
